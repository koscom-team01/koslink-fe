# KOSLINK 서비스 기획서

**뉴스 한 건이 어떤 종목까지 이어지는지 보여주는 온톨로지 기반 주식 영향도 서비스**

| 항목 | 내용 |
|---|---|
| 프로젝트명 | KOSLINK (코스링크) |
| 한 줄 소개 | 최신 뉴스를 클릭하면 온톨로지 그래프가 영향받는 종목과 그 이유를 즉시 보여주는 웹 서비스 |
| 문서 버전 | v1.0 |
| 개발 기간 | 2일 (해커톤) |
| 관련 문서 | `KOSLINK-FRONTEND.md` (프론트엔드 구현 가이드) |

## 1. 기획 배경

### 1.1 문제 정의

개인투자자는 매일 수십 건의 경제 뉴스를 접하지만, **그 뉴스가 어떤 종목을 움직이는지 스스로 판단하지 못한다.**

- 뉴스에 등장하는 기업과 실제로 주가가 움직이는 기업이 다르다. "SK하이닉스 증설" 기사에서 정작 크게 오르는 건 장비를 납품하는 한미반도체다
- 이 연결고리를 알려면 공급망, 경쟁 구도, 소재 흐름을 알아야 한다. 개인이 축적하기 어려운 지식이다
- 정보가 없으니 뉴스를 보고 그 뉴스에 나온 기업만 사거나, 아예 반응하지 못한다

### 1.2 기존 서비스의 한계

| 서비스 유형 | 제공 방식 | 한계 |
|---|---|---|
| 증권사 앱 뉴스 | 종목별 뉴스 나열 | 이미 아는 종목만 볼 수 있음. 새 관련주 발굴 불가 |
| 포털 테마주 | "HBM 테마" 같은 묶음 | 왜 묶였는지 근거 없음. 편입 기준 불투명 |
| 리서치 리포트 | 애널리스트 분석 | 발간 주기가 느리고 분량이 길다 |
| 종목 추천 서비스 | 결과만 제시 | 근거를 볼 수 없고 적중 여부도 공개 안 함 |

공통적으로 **뉴스와 종목 사이의 관계 구조 자체를 보여주지 않는다.** 결과만 있고 경로가 없다.

### 1.3 목적

뉴스와 종목 사이의 관계를 **온톨로지 그래프로 구조화**하고, 이를 시각적으로 탐색할 수 있게 만든다.
사용자가 "왜 이 종목인가"를 스스로 납득할 수 있게 하는 것이 목표다.

## 2. 솔루션

### 2.1 개요

기업, 제품, 테마, 원자재를 노드로 두고 공급·경쟁·조달 같은 관계를 엣지로 연결한 지식 그래프를 구축한다.
뉴스가 들어오면 AI가 그래프의 어느 노드에 걸리는지 판별하고, 그 노드에서 관계를 따라 영향을 전파시킨다.

### 2.2 차별점

**① 단건 매칭이 아니라 관계 그래프로 2단계 이상 추적**

기존 서비스가 "뉴스 → 언급된 기업"에서 멈추는 반면, KOSLINK는 관계를 따라 확장한다.

```
[엔비디아 AI 가속기 증산]
    → AI 데이터센터 (수요 견인)
        → HBM (주력 생산)
            → SK하이닉스 · 삼성전자
                → 한미반도체 · 이오테크닉스
```

**② 상승뿐 아니라 하락 종목을 동시에 제시**

관계에 `polarity` 속성을 부여해 동조 관계와 반대 관계를 구분한다.
리튬 가격 하락 뉴스에서 양극재 3사는 하락, 그 양극재를 사다 쓰는 배터리 셀 업체는 상승으로 갈린다.
**같은 뉴스에서 방향이 갈리는 화면**은 다른 서비스에 없다.

**③ 근거를 그래프 경로에서 생성**

AI가 자유롭게 설명문을 쓰는 게 아니라, 그래프 경로를 템플릿으로 문장화한다.

```
템플릿  "{기점}의 {이벤트}가 {관계}로 이어진 {대상}에 {방향} 요인으로 작용"
출력    "SK하이닉스의 HBM4 증설이 장비 공급 관계로 이어진 한미반도체에 상승 요인으로 작용"
```

환각이 구조적으로 불가능하고, 온톨로지를 쓰는 이유가 그 자체로 증명된다.

**④ 적중률을 공개**

과거 예측과 실제 등락을 대조한 검증 화면을 상시 제공한다. 예측 서비스가 자기 성적을 공개하는 경우는 드물다.

### 2.3 예측하지 않는 것

- 목표 주가, 매수·매도 시점, 투자 조언
- 확률값. **신뢰도 퍼센트를 표시하지 않는다.** 82%와 78%의 차이를 설명할 수 없으면 오히려 신뢰를 깎는다
- 영향의 크기는 **관계상 몇 단계 떨어져 있는지**로만 표현한다 (직접 / 간접 / 확산)

## 3. 타겟 사용자

### 3.1 주 타겟

경제 뉴스를 챙겨 보지만 종목 연결을 스스로 못 하는 **개인투자자**

### 3.2 페르소나

> **박준호 (32세, 직장인, 투자 경력 3년)**
> 출근길에 경제 뉴스를 읽는다. 반도체 증설 기사를 봤지만 어떤 종목이 오를지 몰라 그냥 넘긴다.
> 나중에 관련주가 급등한 걸 보고 아쉬워한다. 테마주 목록은 왜 묶였는지 몰라 신뢰가 안 간다.
>
> **니즈** — 뉴스를 보고 관련 종목을 빠르게 찾고 싶다. 다만 근거 없이 추천만 하는 건 믿지 않는다.

### 3.3 확장 타겟

- 자산운용사·리서치센터 (뉴스-종목 영향도 데이터셋 수요)

## 4. 사용자 시나리오

### 4.1 골든 패스

| 스텝 | 사용자 행동 | 시스템 반응 |
|---|---|---|
| 1 | KOSLINK 접속 | 최신 뉴스 20건 + 전체 관계 그래프 표시 |
| 2 | "SK하이닉스 HBM4 증설" 뉴스 클릭 | 그래프가 기점 중심 동심원으로 재배치 |
| 3 | — | 기점 점등 → 관계선 순차 연결 → 영향 종목 확정 애니메이션 |
| 4 | 우측 패널 확인 | 기사 요약 3줄, 영향 기점, 관련주 4개, 판단 근거 3줄 |
| 5 | 관련주 중 한미반도체 확인 | `직접 영향 · 장비 공급 관계 · SK하이닉스 → 한미반도체` |
| 6 | "지난 예측 적중률 보기" 클릭 | 이번 예측 종목이 포함된 과거 검증만 필터링해 표시 |
| 7 | 관심종목 브리핑에 보유 3종목 입력 | 오늘 뉴스 중 영향 있는 건만 역방향 탐색 결과 표시 |
| 8 | 결과에서 뉴스 클릭 | 뉴스맵으로 복귀, 해당 뉴스 파급 경로 재생 |

8번에서 동선이 순환한다. 발표 흐름이 자연스럽게 닫힌다.

### 4.2 탐색 시나리오 (부가)

전체 관계망에서 임의의 종목을 클릭하면, 배치를 유지한 채 그 종목 기점의 2단계 파급이 강조된다.
말단 종목이라도 허브를 거치면 파급이 급격히 확산되는 구조가 눈으로 보인다.

## 6. 핵심 기능 상세

### 6.1 FR-05 파급 애니메이션

발표에서 시선을 잡는 구간이므로 개발 리소스를 가장 많이 배분한다.

| 시점 | 동작 | 상단 라벨 |
|---|---|---|
| 0.30s | 기점 카드 점등 + 링 2회 확산 | 영향 기점 확인 |
| 0.80s | 단계별 관계선이 순차적으로 그려짐 | 관계 경로 추적 |
| — | 도착 노드가 경유 또는 최종 상태로 전환 | |
| 1.60s | 관련주가 0.21초 간격 확정, 우측 카드 동시 강조 | 영향 종목 산출 |

**정지 상태에서는 아무것도 움직이지 않는다.** 클릭 순간에만 1회 실행하고 멈춘다.

### 6.2 FR-09 판단 근거 3슬롯

LLM이 자유롭게 쓰면 매번 형식이 달라진다. 고정 3슬롯으로 강제한다.

| 슬롯 | 내용 | 생성 주체 |
|---|---|---|
| 이벤트 | 뉴스가 말하는 사실 | LLM 요약에서 추출 |
| 파급 경로 | 왜 이 종목까지 오는가 | **그래프 경로 템플릿** |
| 과거 사례 | 유사 뉴스 시 실제 등락 | 검증 데이터 조회 |

두 번째 슬롯을 LLM이 아니라 데이터에서 만드는 것이 핵심이다.

### 6.3 FR-12 전체 관계망 노드 클릭

**배치를 바꾸지 않는다.** 전체 맥락 속 위치를 봐야 하는 뷰이기 때문이다.

| 단계 | 노드 | 엣지 |
|---|---|---|
| 기점 | 검정 카드 + 흰 테두리 | — |
| 1단계 | 흰 배경 + 진한 주황 테두리 | 진한 주황 |
| 2단계 | 연한 주황 배경 | 연한 주황 |
| 무관 | 90% 투명 | 거의 안 보임 |

멀어질수록 옅어져 파급 범위가 농도로 읽힌다.

### 6.4 FR-19 관심종목 브리핑

일반 대화형 챗봇이 아니다. **그래프 역방향 탐색 기능**이다.

```
입력: 삼성전자, 한미반도체, LG에너지솔루션
출력: 오늘 뉴스 20건 중 2건이 관심종목에 영향을 줍니다
      ↑ 한미반도체   [SK하이닉스 HBM4 증설]  장비 공급 · 직접 영향
      ↓ 삼성전자     [SK하이닉스 HBM4 증설]  경쟁 관계 · 직접 영향
      - LG에너지솔루션  관련 뉴스 없음
```

동작 원리는 각 종목 노드에서 2단계 이내 연결 집합을 만들고, 오늘 분석된 뉴스의 영향 노드와 교집합을 구하는 것이다. LLM 없이도 동작하며, 문장 다듬기에만 LLM을 쓴다.

기본 흐름이 `뉴스 → 종목`이므로 브리핑은 반대 방향을 담당한다. 온톨로지가 양방향으로 쓰이는 근거가 된다.

### 6.5 FR-17 검증 컨텍스트 필터

전체 검증을 보여주면 "지금 이 예측을 믿어도 되나"라는 질문에 답하지 못한다.
뉴스 상세에서 진입하면 **이번 예측에 등장한 종목이 포함된 과거 검증만** 필터링하고 상단에 배너를 띄운다.

> 이번 예측에 등장한 **SK하이닉스 · 한미반도체 · HPSP 외 2종목**이 포함된 과거 검증 **4건**만 보고 있습니다

## 8. 데이터 및 외부 연동

### 8.1 온톨로지 구축 범위

실시간 생성은 2일 내 불가능하다. **사전 구축 방식**으로 간다.

| 항목 | 목표 |
|---|---|
| 섹터 | 반도체, 2차전지, 방산 3개 |
| 노드 | 36개 (기업 24, 제품·테마·원자재 12) |
| 엣지 | 52개 |
| 구축 방법 | DART 사업보고서와 증권사 리포트 참고, LLM 초안 생성 후 수작업 검수 |

LLM의 역할은 **뉴스가 그래프의 어느 노드에 걸리는지 판별**하는 데 한정한다.

### 8.2 관계 유형

| 관계 | polarity | 예시 |
|---|---|---|
| 공급 / 조달 | +1 | SK하이닉스 ← 한미반도체 (장비 공급) |
| 생산 | +1 | 에코프로비엠 → 양극재 |
| 원재료 | +1 | 양극재 ← 리튬 |
| 수요 견인 | +1 | AI 데이터센터 → HBM |
| 경쟁 / 대체 | **-1** | SK하이닉스 ↔ 삼성전자 |

### 8.3 외부 데이터 소스

| 구분 | 소스 | 용도 | 선결 검증 |
|---|---|---|---|
| 뉴스 | 네이버 뉴스 검색 API | 목록, 제목, 요약, 링크 | 본문 전문 미제공 전제로 설계 |
| 종목 마스터 | KRX 정보데이터시스템 | 종목코드, 업종, 시가총액 | 코드 매핑 정확도 |
| 주가 | KRX 일별시세 | 검증 화면 등락률 | 과거 30일 조회 가능 여부 |
| 기업 관계 | DART 공시 | 온톨로지 엣지 근거 | 수작업 병행 |
| LLM | OpenAI 또는 Claude API | 요약, 노드 매칭, 문장 다듬기 | 응답 3초 이내 |

### 8.4 검증 데이터 생성

실시간 계산하지 않는다. 과거 뉴스 40~50건을 **사전 배치로 예측 → 실제 등락률 조인 → 정적 결과 저장**한다.
프론트는 읽기만 한다. 이 구조가 아니면 데모 당일 반드시 문제가 생긴다.

## 14. 발표 구성 (5분 기준)

| 순서 | 시간 | 내용 |
|---|---|---|
| 1 | 40초 | 문제 — 뉴스는 보는데 어떤 종목이 오를지 모른다 |
| 2 | 20초 | 솔루션 한 문장 + 차별점 3가지 |
| 3 | **150초** | **라이브 데모** |
| 4 | 40초 | 기술 포인트 — 온톨로지 구조, 경로 기반 근거 생성 |
| 5 | 30초 | 검증 화면 — 우리는 성적을 공개한다 |
| 6 | 20초 | 수익 모델 + 확장 계획 |

### 데모 순서

1. **리튬 가격 뉴스** 선택 — 양극재 3사는 하락, LG에너지솔루션만 상승으로 갈리는 화면
2. 판단 근거 3줄 확인 — 그래프 경로에서 생성된 문장
3. **전체 관계망 전환** — 클러스터 조립 후 그 뉴스의 파급이 전체 망 위에 얹힘
4. **삼성전자 클릭** — 배치 유지한 채 2단계 파급 강조
5. **검증 탭** — 지난 예측 적중률 공개
6. **관심종목 브리핑** — 역방향 탐색, 결과에서 뉴스맵으로 복귀

1번이 가장 강하다. "같은 뉴스인데 방향이 갈린다"가 한 화면에서 증명된다.
